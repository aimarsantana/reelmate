# analysis/ — "How many stars would I give it?" (Phase 2 research)

Data-science side of Reelmate. Question: **given a film I have not rated, what rating (0.5–5★) would I give it, and why?**

📓 **Notebook:** [`notebooks/01_rating_model.ipynb`](notebooks/01_rating_model.ipynb) — executed, with all outputs, readable directly on GitHub.

> Parte de ciencia de datos de Reelmate (fase 2). El cuaderno, en inglés, compara modelos que predicen la nota que le pondría un usuario a una película, con validación cruzada repetida y sin fuga de datos. El modelo elegido (Ridge) se reimplementa en TypeScript y se entrena en el navegador (`web/lib/model.ts`).

## Results (263 rated films, 5-fold CV × 10 repetitions, same folds for every model)

| Model | MAE (★) | RMSE | Within 0.5★ |
|---|---|---|---|
| A. Always my mean | 0.658 | 0.827 | 49.0 % |
| B. My mean + deviation of the (vote-adjusted) TMDB score | 0.517 | 0.662 | 58.1 % |
| **Light fallback (TMDB + genres), nested CV (official)** (→ web) | **0.492** | 0.637 | 61.6 % |
| *Light fallback, setup fixed beforehand (comparison)* | *0.491* | *0.635* | *61.1 %* |
| **Ridge, nested CV (official)** (→ web) | **0.483** | 0.619 | 59.8 % |
| *Ridge, setup fixed beforehand (comparison)* | *0.479* | *0.609* | *59.6 %* |
| k-NN | 0.534 | 0.689 | 56.5 % |
| Random Forest (most accurate) | 0.473 | 0.609 | 61.6 % |
| Gradient Boosting | 0.493 | 0.627 | 60.0 % |

* The TMDB score does most of the work; genres, decade and a Bayesian-smoothed director/cast encoding add a modest but real gain (Ridge −6.6 % MAE vs. baseline B).
* **Unreliable TMDB scores** (e.g. a perfect 5.0 from one vote) are shrunk towards the global mean: `adjusted = (v·R + m·C) / (v + m)` with `C = 6.5`. The error is flat for `m` between ~100 and 1000 (the web fixes `m = 500`; the nested CV tunes it inside each fold).
* Official figures use **nested CV** (hyper-parameters chosen in an inner loop), which removes the optimism of picking the setup on the same folds (+0.004★ for Ridge). Random Forest is best (0.473) but its edge over Ridge's plain fit is only 0.005★ and not significant (*p* = 0.16), so **Ridge goes to the web**: it is additive (exact "+0.6 because Nolan" explanations) and trains in milliseconds in the browser. Gradient Boosting is worse than Ridge with ~260 labels.
* Data leakage is avoided by fitting the target encoding (and every other learned statistic) **inside each training fold**, with leave-one-out inside the fold. The notebook shows how a leaky pipeline would fake a ~0.29★ improvement.
* With fewer than ~60 ratings the director/cast signal is too sparse; the web ships both models. For each user with ≥ 30 ratings it cross-validates both on their own ratings and uses the personal one if its error is lower than or equal to the fallback's (otherwise the fallback); below 30 ratings it always uses the fallback.

## Reproduce

```bash
cd analysis
python -m venv .venv
.venv\Scripts\activate            # Windows  (source .venv/bin/activate on macOS/Linux)
pip install -r requirements.txt

# 1. Build the dataset (needs the Letterboxd export .zip in the repo root and TMDB_API_KEY in web/.env.local)
python src/build_dataset.py       # writes analysis/data/films.json (git-ignored)

# 2. Open / re-run the notebook
jupyter lab notebooks/01_rating_model.ipynb

# 3. (Optional) refresh the reference numbers used by the TypeScript equivalence test
python src/export_reference.py
```

`analysis/data/` is not committed: it contains raw TMDB data and is regenerated by the script.

## Layout

```
src/build_dataset.py       Letterboxd .zip + TMDB  ->  data/films.json
src/features.py            FeatureBuilder (per-fold target encoding), baselines, metrics, CV helpers
src/models.py              Ridge (partially penalised), TMDB+genre fallback, k-NN, RF, GB
src/export_reference.py    Reference results for the TypeScript test
notebooks/01_rating_model.ipynb
```
